LRU 数字存储模块开发文档1. 概述本文档描述一个基于 LRU（Least Recently Used，最近最少使用）淘汰策略的数字存储模块。该模块用于存储用户输入的数字，并根据配置文件指定的容量上限进行自动淘汰。模块对外提供访问、插入和修改操作，每次操作都会将目标数字标记为“最近刚刚使用过”，从而保证缓存中始终保留最常用的数字，淘汰长期未使用的数字。2. 需求描述2.1 功能需求容量配置模块的容量上限由配置文件提供，配置文件为一个简单的文本文件，内容为一个正整数，表示最多可存储的数字个数。例如 capacity.conf 中写入 5 表示缓存最多保存 5 个不同的数字。数字存储模块存储的是数字（整数或浮点数），每个数字在缓存中作为键存在，值可以是数字本身或其他关联信息（本实现中值存储为数字本身，便于后续扩展）。操作定义访问（get）：用户查询某个数字是否在缓存中。若存在，则将该数字标记为最近使用，并返回其值；若不存在，返回 None 或抛出异常（建议返回 None 并提示未找到）。插入（put）：用户插入一个新数字。如果该数字已存在，则更新其值并标记为最近使用；如果不存在，则检查当前缓存大小。若未达到容量上限，直接插入；若已满，则先淘汰最久未使用的数字，再插入新数字。修改（update）：修改某个已存在数字的值。等同于对该数字执行一次“插入”操作，同时更新其最近使用状态。如果数字不存在，则视为插入操作。LRU 淘汰策略当缓存达到容量上限且需要插入新数字时，淘汰最长时间未被访问、插入或修改过的数字。被淘汰的数字将从缓存中永久移除。2.2 非功能需求时间复杂度：访问、插入、修改操作均应在 O(1) 平均时间内完成。空间复杂度：额外空间开销为 O(n)，n 为当前缓存中的元素个数。线程安全：如果模块需要在多线程环境下使用，应保证操作的原子性（本示例暂不考虑，但可扩展）。3. 设计思路3.1 数据结构选择为满足 O(1) 时间复杂度的要求，采用 哈希表 + 双向链表 的组合结构：哈希表（dict）：键为数字，值为指向双向链表节点的引用，用于 O(1) 定位节点。双向链表：维护缓存中所有数字的访问顺序，链表头部为最近使用的节点，尾部为最久未使用的节点。每次访问或修改都将节点移动到头部；插入新节点时添加到头部；缓存满时删除尾部节点。Python 标准库中的 collections.OrderedDict 可以简化实现，其内部就是哈希表 + 双向链表。但为了更清晰地展示 LRU 逻辑，本示例采用自定义双向链表节点和字典的组合。3.2 模块划分LRUCache 类：核心缓存类，包含容量、字典和链表头尾哨兵节点。配置文件读取函数：从指定路径读取容量值。用户交互接口：命令行或函数调用，处理访问、插入、修改操作。4. 详细设计4.1 已存在，更新节点值并移动到头部。若不存在，创建新节点，加入 cache 和链表头部。检查缓存大小是否超过 capacity，若超过，移除尾部节点（最久未使用），并从 cache 中删除对应键。update(key, value)：直接调用 put(key, value)，效果相同。4.4 Python 实现示例pythonclass _Node:    """双向链表节点"""    def __init__(self, key, value):        self.key = key        self.value = value        self.prev = None        self.next = Noneclass LRUCache:    def __init__(self, capacity: int):        if capacity <= 0:            raise ValueError("容量必须为正整数")        self.capacity = capacity        self.cache = {}  # key -> _Node        self.head = _Node(0, 0)  # 哨兵头节点        self.tail = _Node(0, 0)  # 哨兵尾节点        self.head.next = self.tail        self.tail.prev = self.head    def _add_node(self, node):        """在头部插入节点"""        node.prev = self.head        node.next = self.head.next        self.head.next.prev = node        self.head.next = node    def _remove_node(self, node):        """从链表中移除节点"""        prev = node.prev        nxt = node.next        prev.next = nxt        nxt.prev = prev    def _move_to_head(self, node):        """将节点移动到头部"""        self._remove_node(node)        self._add_node(node)    def _pop_tail(self):        """移除并返回尾部节点"""        res = self.tail.prev        self._remove_node(res)        return res    def get(self, key):        """访问操作：若存在则标记为最近使用并返回值，否则返回None"""        if key in self.cache:            node = self.cache[key]            self._move_to_head(node)            return node.value        return None    def put(self, key, value):        """插入/更新操作"""        if key in self.cache:            # 已存在：更新值并移动到头部            node = self.cache[key]            node.value = value            self._move_to_head(node)        else:            # 新节点            new_node = _Node(key, value)            self.cache[key] = new_node            self._add_node(new_node)            if len(self.cache) > self.capacity:                # 超出容量，淘汰最久未使用（尾部）                tail_node = self._pop_tail()                del self.cache[tail_node.key]    def update(self, key, value):        """修改操作：等同于插入/更新"""        self.put(key, value)    def __len__(self):        return len(self.cache)    def __contains__(self, key):        return key in self.cachedef load_capacity(config_path='capacity.conf'):    """从配置文件读取容量"""    with open(config_path, 'r') as f:        return int(f.readline().strip())# 使用示例if __name__ == '__main__':    capacity = load_capacity()  # 假设 capacity.conf 内容为 3    cache = LRUCache(capacity)    # 插入    cache.put(1, 10)    cache.put(2, 20)    cache.put(3, 30)    print(cache.get(1))  # 访问1，返回10，并标记1为最近使用    cache.put(4, 40)     # 插入4，容量已满，淘汰最久未使用的2    print(cache.get(2))  # 返回None，因为2已被淘汰    print(cache.get(3))  # 返回30    print(cache.get(1))  # 返回10，1仍然是最近使用    cache.update(3, 33)  # 修改3的值，标记为最近使用    print(cache.get(3))  # 返回336. 测试要点建议编写单元测试覆盖以下场景：容量为 1：插入两个数字，第一个被淘汰。正常插入和访问：访问操作改变 LRU 顺序。更新已有数字：更新后成为最近使用。容量未满时的插入：不发生淘汰。获取不存在的数字：返回 None 或适当提示。容量配置错误（如 0 或负数）：应抛出异常。7. 注意事项本实现中键和值都为数字，如果未来需要存储更复杂的数据，只需修改值类型即可。在多线程环境下，LRUCache 的方法不是线程安全的。如需线程安全，可在方法外部加锁（如 threading.Lock），保证操作的原子性。配置文件路径可以根据实际部署调整，建议使用绝对路径或相对于项目根目录的路径。如果用户输入的键值类型不一致（如字符串和数字混用），需要提前进行类型转换或校验。8. 总结本模块通过 LRU 策略管理用户输入的数字，能够高效地保持最近使用的数字，自动淘汰长期未使用的数据。其核心是哈希表与双向链表的结合，所有操作的平均时间复杂度为 O(1)，满足实时性要求。开发者可以根据实际需求对代码进行扩展，例如增加持久化存储、分布式支持或更复杂的淘汰策略。
